AI by Hand - Deep Learning With a Pencil and Paper

5 min read

There is a specific kind of understanding you only get by doing the arithmetic yourself. You can read that a layer computes $\text{ReLU}(Wx + b)$ a hundred times. Then you multiply one row of $W$ by $x$ with a pencil, watch a negative number get clipped to zero, and something clicks that no amount of reading produced.

That is the idea behind AI by Hand ✍️, a series of exercises by Prof. Tom Yeh at the University of Colorado Boulder. He takes the machinery of modern AI - neurons, backpropagation, attention, transformers - and shrinks it down to small integer matrices on a grid. You fill in the blanks one cell at a time. Nothing is hidden behind a library call. If you enjoy what follows, his newsletter, AI by Hand ✍️ , has hundreds more.

This post is a set of four exercises in that spirit, built as interactive worksheets. Every number was computed and checked by a program, and the backpropagation gradients were verified against numerical derivatives.

How to use them. Each worksheet highlights the cells you need in blue and the cell to compute in orange. Work it out on paper, then press Step to see the answer and the arithmetic. Back goes back a step. Nothing plays by itself: the point is that you do it.

Exercise 1: One Layer

A layer of a neural network is a set of neurons, all looking at the same input. Each neuron has its own weights (one row of $W$) and its own bias. It computes a weighted sum of the inputs, adds the bias, then applies an activation function. With four neurons and three inputs:

$$a = \text{ReLU}(Wx + b), \qquad W \in \mathbb{R}^{4 \times 3},; x \in \mathbb{R}^3,; b \in \mathbb{R}^4.$$

Notice what ReLU did to the fourth neuron. Its weighted sum came out negative, so its output is zero: for this input it says nothing at all. Which neurons stay silent for which inputs is a large part of what a trained network has learned.

Exercise 2: Softmax

A classifier’s last layer produces arbitrary scores, called logits. Softmax turns them into probabilities:

$$\text{softmax}(z)_i = \frac{e^{z_i}}{\sum_j e^{z_j}}.$$

To keep the arithmetic exact by hand, this exercise uses $2^{z}$ instead of $e^{z}$. That is not a cheat: $2^{z} = e^{z \ln 2}$, so it is ordinary softmax with the scores multiplied by $\ln 2 \approx 0.69$, the same as running it at a temperature of $1/\ln 2$. The ranking and the overall shape are identical.

One practical trick, used in every real implementation: subtract the largest logit from all of them before exponentiating. It cancels out in the fraction, so the answer is unchanged, but it stops $e^{z}$ from overflowing when the logits are large.

Exercise 3: Backpropagation

Training means nudging every weight in whichever direction lowers the loss. To do that you need the derivative of the loss with respect to every weight. Backpropagation computes all of them in one backward sweep, using the chain rule: the gradient arriving at a node gets multiplied by that node’s local derivative and passed on to its inputs.

The network here is as small as it can be while still being interesting: two inputs, two hidden ReLU neurons, one output, squared-error loss $L = \tfrac{1}{2}(y - t)^2$.

Three things to notice, because they are true of every network:

  • The forward values are reused going backward. $\partial L / \partial w_2$ needs $h$, and $\partial L / \partial W_1$ needs $x$. That is why training frameworks keep every layer’s activations in memory until the backward pass is done.
  • Blame flows back through the same weights. $\partial L / \partial h$ is the output error times $w_2$: a hidden neuron is blamed in proportion to how strongly it influenced the output.
  • A dead ReLU blocks the gradient. The first hidden neuron was negative, so it output zero, so it receives zero gradient, so its incoming weights don’t change. If that happens for every input, the neuron never recovers: the “dying ReLU” problem.

Exercise 4: Self-Attention

Attention is how the tokens in a transformer exchange information. Each token produces a query (what am I looking for?), a key (what do I contain?) and a value (what do I pass on if chosen?), each by multiplying its vector by a weight matrix. Then:

$$\text{Attention}(Q, K, V) = \text{softmax}\left(QK^\top\right) V.$$

Real transformers divide the scores by $\sqrt{d}$ before the softmax, to keep them from growing with the vector size. With $d = 2$ we skip it so the numbers stay whole, and we use $2^{z}$ softmax again. The exercise has three stages; use the tabs to move between them.

Each output row is a blend of the value rows, weighted by how well that token’s query matched each key. Nothing about the computation knows which token is which or where it sits in the sentence. That is why transformers add positional encodings , and why a full model runs many of these heads side by side in every layer.

Why Bother Doing It By Hand?

Because the abstractions hide exactly the things that go wrong in practice:

Exercise What the arithmetic makes obvious
One layer A layer is one matrix multiply plus a cheap nonlinearity; ReLU can switch neurons off entirely
Softmax Scores are exponentiated, so small differences become large ones; temperature controls how much
Backpropagation Gradients reuse forward activations, scale with the weights they pass through, and stop at dead ReLUs
Self-attention Every token is scored against every other: $n$ tokens means $n^2$ scores, the root of attention’s cost on long inputs

Once you have done each of these once, the shapes in a PyTorch error message stop being mysterious. You know what was supposed to multiply what.
