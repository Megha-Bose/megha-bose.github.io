SAT - The Problem at the Heart of NP

Aug 2021
6 min read

Helpful context:

  • NP-Completeness - Why Some Problems Are All the Same Problem
  • Constraint Satisfaction - Searching Smart, Not Exhaustively

In 2016 Marijn Heule, Oliver Kullmann and Victor Marek settled the Boolean Pythagorean triples problem with a SAT solver. Can the positive integers be colored red and blue so that no Pythagorean triple $a^2 + b^2 = c^2$ is all one color? The numbers 1 to 7,824 can be. The numbers 1 to 7,825 can’t. The computer-checked proof took 200 terabytes, far more than any human could read in a lifetime.

SAT is NP-complete, so in theory it’s as hard as anything in NP. Yet SAT solvers routinely handle millions of variables. The gap between “NP-complete in the worst case” and “fast in practice” is enormous for SAT, and understanding it is one of the great stories in modern computing.

Boolean Satisfiability

A formula in conjunctive normal form (CNF) is an AND of clauses, each an OR of literals: a variable $x_i$ or its negation $\neg x_i$.

$$\varphi = (x_1 \vee \neg x_2 \vee x_3) \wedge (\neg x_1 \vee x_2) \wedge (x_2 \vee \neg x_3)$$

SAT asks whether some true/false assignment makes every clause true. Here $x_1 = x_2 = $ true, $x_3 = $ false works. Each clause forbids exactly one combination of its own variables, the one making all its literals false; a solution has to avoid every forbidden combination at once.

SAT is NP-complete: that’s the Cook-Levin theorem . Restricting clause size changes the story sharply, though.

2-SAT Is Easy

With at most two literals per clause, SAT is solvable in linear time. Every clause $(a \vee b)$ says the same as two implications: $\neg a \Rightarrow b$ and $\neg b \Rightarrow a$. Build the implication graph, with a vertex for every literal and an edge for every implication, and find its strongly connected components .

If some $x_i$ and $\neg x_i$ land in the same component, each forces the other, which is a contradiction: unsatisfiable. Otherwise, set each variable to whichever of $x_i$ and $\neg x_i$ comes later in the topological order of the components. The whole thing is $O(n + m)$ for $n$ variables and $m$ clauses.

Going from 2 literals per clause to 3 is one of the sharpest cliffs in complexity theory: 2-SAT is in P, 3-SAT is NP-complete.

DPLL: Decide, Propagate, Backtrack

The DPLL algorithm (Davis, Putnam, Logemann and Loveland, 1962) is still the backbone of SAT solving: backtracking search, plus propagation.

  • Unit propagation: if every literal in a clause is false except one unset literal, that literal must be true. Each forced assignment can make more clauses unit, setting off a cascade.
  • Pure literals: a variable that appears only positively (or only negatively) can simply be set to satisfy all its clauses.

CDCL: Learning From Mistakes

Conflict-driven clause learning (CDCL) turned SAT from a research curiosity into an industrial tool. When plain DPLL hits a conflict, it backtracks one step and tries the other value. CDCL first works out why the conflict happened, and remembers it.

  1. Record the reasons. For every forced assignment, note which clause forced it. Together these form an implication graph from the decisions to the conflict.
  2. Find a cut. A unique implication point (UIP) is an assignment at the current decision level that every path from that level’s decision to the conflict passes through. Solvers usually take the one closest to the conflict.
  3. Learn a clause. Cutting the graph there gives a new clause that says, compactly, “this combination always fails”. It’s logically implied by the original formula, so it can’t remove any real solution.
  4. Backjump. Jump straight back to the second-highest decision level in the learned clause, often skipping many levels and thousands of hopeless branches at once.

“Doesn’t the formula keep growing?" It does, but the learned clauses are implied by the original, so the set of solutions never changes, while the search shrinks dramatically: any future branch heading for the same conflict is cut off immediately by unit propagation on the learned clause. Solvers periodically delete the least useful learned clauses to keep memory in check.

In effect, the solver builds a compressed record of every dead end it has already explored.

Why SAT Solvers Are Fast in Practice

Worst-case hardness is rare in real instances. Formulas from hardware verification, software analysis and planning have structure: variables that interact form loose, hierarchical clusters rather than one tangled web, and related variables appear together. Clause learning feeds on exactly that.

Modern solvers add three more tricks:

  • VSIDS: prefer to branch on variables that appeared in recent conflicts.
  • Restarts: periodically throw away the current search state while keeping the learned clauses, to escape unproductive regions.
  • Phase saving: when revisiting a variable, retry its last value.

The truly hard instances are random 3-SAT at the phase transition. As the ratio of clauses to variables crosses about 4.27, random formulas switch abruptly from almost always satisfiable to almost never. Right at that threshold there’s no structure to exploit, and even the best solvers struggle. Industrial instances sit far from it.

Applications

  • Hardware verification. Every major chip company encodes circuits as CNF and asks whether any input can produce a wrong output. A satisfying assignment is a counterexample, a bug; “unsatisfiable” proves the property holds. This is where SAT saves billions in chip respins.
  • Software verification. SMT solvers like Microsoft’s Z3, which extend SAT with arithmetic, arrays and more, check programs for assertion failures, overflows and security holes.
  • Planning and scheduling. Variables say which action happens at which time step; clauses encode preconditions and effects.
  • Cryptanalysis. Some attacks on weakened hash functions and ciphers become SAT instances, which solvers sometimes crack faster than brute force.
