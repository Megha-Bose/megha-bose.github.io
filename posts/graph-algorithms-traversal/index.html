Graph Algorithms & Traversal - Maps, Networks, and Hidden Order

Aug 2021
10 min read

In 1735 the city of Königsberg had seven bridges joining two river islands and the two banks, and a puzzle nobody could solve: can you walk through the city crossing every bridge exactly once? Leonhard Euler proved you can’t, and in doing so invented graph theory.

His move was to throw away everything that didn’t matter. Streets, distances and the shape of the river were irrelevant; all that counted was which landmasses were joined, and how many times. Dots for landmasses, lines for bridges. Then the answer was clean: a walk using every line exactly once, an Eulerian path, needs at most two dots with an odd number of lines. All four of Königsberg’s landmasses had an odd number. No such walk exists.

Dots and lines - that abstraction is a graph.

Graphs: The Basics

A graph $G = (V, E)$ is a set of vertices $V$ and edges $E$ joining pairs of them. Edges may be directed, one-way like web links or one-way streets, or undirected; and weighted, carrying a distance, cost or capacity, or unweighted.

Two ways to store one:

  • Adjacency matrix: a $V \times V$ grid, with entry $(i, j)$ set if the edge exists. Checking an edge is $O(1)$, but it always takes $O(V^2)$ space.
  • Adjacency list: each vertex keeps a list of its actual neighbours, $O(V + E)$ space. Real graphs - roads, social networks, the web - are sparse, with far fewer than $V^2$ edges, so lists win almost everywhere.

BFS and DFS

The two fundamental ways to explore a graph differ in a single detail: whether the vertices waiting to be explored sit in a queue or a stack.

Breadth-first search uses a queue, first in first out, so it finishes everything at distance $k$ before touching distance $k + 1$, like ripples from a stone. So in an unweighted graph, BFS finds shortest paths: the first time it reaches a vertex is along a path with the fewest edges.

from collections import deque

def bfs(graph, source):
    dist, parent = {source: 0}, {source: None}
    queue = deque([source])
    while queue:
        u = queue.popleft()
        for v in graph[u]:
            if v not in dist:              # first visit is the shortest
                dist[v] = dist[u] + 1
                parent[v] = u
                queue.append(v)
    return dist, parent                    # parent pointers trace each shortest path back

Depth-first search uses a stack, usually the call stack via recursion: dive as deep as possible, and back up only at a dead end. Its paths aren’t shortest, but its structure is very useful. A vertex finishes only after everything reachable from it has finished, and running into a vertex that’s still on the current path reveals a cycle.

Code: DFS with cycle detection and finish order 
def dfs(graph):
    visited = set()
    in_stack = set()   # nodes on the current recursion path
    finish_order = []
    has_cycle = [False]

    def dfs_visit(u):
        visited.add(u)
        in_stack.add(u)
        for v in graph[u]:
            if v not in visited:
                dfs_visit(v)
            elif v in in_stack:
                has_cycle[0] = True  # v is an ancestor: cycle found
        in_stack.discard(u)
        finish_order.append(u)       # appended after all descendants finish

    for v in graph:
        if v not in visited:
            dfs_visit(v)

    return finish_order, has_cycle[0]

# Example: directed graph A→B→C→D, A→D
graph = {'A': ['B', 'D'], 'B': ['C'], 'C': ['D'], 'D': []}
finish_order, cycle = dfs(graph)
# finish_order = ['D', 'C', 'B', 'A']  (reversed = topological order)
# cycle = False

Both visit every vertex and edge once: $O(V + E)$.

Bipartiteness comes almost for free from BFS. A graph is bipartite, two-colorable with every edge joining different colors, exactly when it has no odd cycle. Color the BFS layers alternately; an edge inside one layer means it isn’t.

Topological Sort

In a dependency graph, an edge $u \to v$ means “$u$ before $v$": a module imported by another, a course that’s a prerequisite for another. A topological order lists every vertex after all of its prerequisites. It exists exactly when there’s no cycle.

Kahn’s algorithm keeps a count of unmet prerequisites for each vertex. Output anything whose count is zero, cross off its outgoing edges, and repeat:

This is an interactive animation. It needs JavaScript to run.

If the output ends up shorter than the graph, some counts never reached zero: there’s a cycle, so no valid order exists.

The DFS way is just as fast: run DFS and reverse the finish order. If $u \to v$, DFS finishes $v$ (and everything after it) before it can finish $u$, so reversing puts $u$ first. For a chain $A \to B \to C$: finish order C, B, A; reversed, A, B, C.

Code: both topological sorts 
from collections import deque, defaultdict

def topo_sort_dfs(graph):
    finish_order, has_cycle = dfs(graph)
    if has_cycle:
        raise ValueError("cycle: no topological order exists")
    return finish_order[::-1]

def topo_sort_kahn(graph):
    in_degree = defaultdict(int)
    for u in graph:
        for v in graph[u]:
            in_degree[v] += 1
    ready = deque(v for v in graph if in_degree[v] == 0)
    order = []
    while ready:
        u = ready.popleft()
        order.append(u)
        for v in graph[u]:
            in_degree[v] -= 1
            if in_degree[v] == 0:
                ready.append(v)
    if len(order) < len(graph):
        raise ValueError("cycle: no topological order exists")
    return order

build = {"main": ["utils", "config"], "utils": ["io"], "config": ["io", "log"],
         "io": ["stdlib"], "log": ["stdlib"], "stdlib": []}
print(topo_sort_kahn(build))   # ['main', 'utils', 'config', 'io', 'log', 'stdlib']

Kahn’s version detects cycles naturally and never recurses, so it can’t overflow the stack on huge graphs. Both are $O(V + E)$.

Strongly Connected Components

In a directed graph, a strongly connected component (SCC) is a maximal group of vertices that can all reach each other. Two cycles joined by a one-way bridge form two SCCs: you can cross the bridge, but never come back.

graph LR subgraph SCC1["SCC 1: A, B, C"] A --> B B --> C C --> A end subgraph SCC2["SCC 2: D, E, F"] D --> E E --> F F --> D end C -->|"one-way bridge"| D

Kosaraju’s algorithm finds every SCC in $O(V + E)$ with two DFS passes:

  1. Run DFS on $G$ and record the finish order.
  2. Reverse every edge, giving $G^T$.
  3. Take vertices in reverse finish order. Each DFS on $G^T$ from a still-unvisited vertex collects exactly one SCC.

Here, DFS from A finishes F, E, D, then C, B, A, since it crosses the bridge before finishing A’s cycle. On $G^T$ the bridge points backwards:

graph LR subgraph SCC1["SCC 1: A, B, C"] B --> A C --> B A --> C end subgraph SCC2["SCC 2: D, E, F"] E --> D F --> E D --> F end D -->|"reversed bridge"| C

DFS from A on $G^T$ collects A, B and C, but can’t cross the reversed bridge, so it stops. The next vertex, D, collects D, E and F. Reversing the edges keeps every cycle a cycle, but turns the bridges around, so each search stays trapped inside one component.

Code and proof 
from collections import defaultdict

def kosaraju(graph):
    # Step 1: DFS on original graph to get finish order
    visited = set()
    finish_order = []

    def dfs1(u):
        visited.add(u)
        for v in graph[u]:
            if v not in visited:
                dfs1(v)
        finish_order.append(u)  # append after all descendants done

    for v in graph:
        if v not in visited:
            dfs1(v)

    # Step 2: Build transpose (reverse all edges)
    transposed = defaultdict(list)
    for u in graph:
        for v in graph[u]:
            transposed[v].append(u)

    # Step 3: DFS on transpose in reverse finish order
    visited.clear()
    sccs = []

    def dfs2(u, component):
        visited.add(u)
        component.append(u)
        for v in transposed[u]:
            if v not in visited:
                dfs2(v, component)

    for u in reversed(finish_order):
        if u not in visited:
            component = []
            dfs2(u, component)
            sccs.append(component)

    return sccs

# Example
graph = {
    'A': ['B'], 'B': ['C'], 'C': ['A', 'D'],
    'D': ['E'], 'E': ['F'], 'F': ['D'],
}
print(kosaraju(graph))  # [['A', 'C', 'B'], ['D', 'F', 'E']]

Proof of correctness. The claim is: each DFS call in step 3 outputs exactly one SCC.

To see why, think about the condensation of $G$ - the DAG formed by collapsing each SCC to a single node and keeping one edge between pairs of SCCs. The condensation is always a DAG (if it had a cycle, all the SCCs in that cycle would merge into one).

Key Lemma. If there is an edge from SCC $C$ to SCC $C'$ in the condensation (some path from $C$ to $C'$ in $G$ but not back), then the last vertex of $C$ to finish has a higher finish time than the last vertex of $C'$ to finish. More precisely, $f(C) > f(C')$ where $f(C) = \max_{v \in C} f(v)$.

Proof. Let $u$ be the first vertex discovered by DFS in either $C$ or $C'$.

  • If $u \in C$: at the moment $u$ is discovered, all vertices of $C'$ are unvisited. Since there is a path from $u$ (in $C$) to $C'$, the DFS subtree rooted at $u$ will eventually reach and fully explore $C'$ before $u$ finishes. Therefore every vertex in $C'$ finishes before $u$ finishes, so $f(C') < f(u) \leq f(C)$.
  • If $u \in C'$: there is no path from $C'$ back to $C$ (different SCCs, edge only goes $C \to C'$). So the DFS subtree rooted at $u$ explores all of $C'$ and never reaches $C$. All of $C'$ finishes before DFS ever visits $C$, giving $f(C') < f(C)$.

In both cases, $f(C) > f(C')$. $\square$

Consequence: the source is processed first. The vertex $u$ with the globally maximum finish time belongs to some SCC $C_1$. If $C_1$ had any incoming edge $C' \to C_1$ in the condensation, the Key Lemma would require $f(C') > f(C_1)$, contradicting $u$ being the global maximum. So $C_1$ has no incoming edges in the condensation of $G$ - it is a source.

Step 3 stays within one SCC. In $G^T$ (all edges reversed), the condensation is also reversed. Since $C_1$ was a source in $G$’s condensation, it becomes a sink in $G^T$’s condensation - no outgoing edges leave $C_1$ in $G^T$. DFS from $u \in C_1$ in $G^T$ can only travel along $G^T$ edges and is therefore confined to $C_1$.

Meanwhile, every vertex in $C_1$ is reachable from $u$ in $G^T$: since $u$ and $v$ are in the same SCC, there is a path from $v$ to $u$ in $G$, and reversing it gives a path from $u$ to $v$ in $G^T$. So DFS from $u$ collects exactly $C_1$.

Induction. After marking $C_1$ as visited, the remaining unvisited vertices form a subgraph. The next unvisited vertex with the highest finish time belongs to the source SCC of that subgraph’s condensation, and the same argument applies. Each DFS call in step 3 identifies exactly one SCC, peeling the condensation from source to sink one layer at a time. $\square$

Connected Components, Bridges and Articulation Points

In an undirected graph, each fresh DFS or BFS started from the outer loop finds one connected component. One DFS also finds the articulation points, vertices whose removal disconnects the graph, and bridges, edges whose removal disconnects it, in $O(V + E)$: a vertex $u$ is an articulation point if some child in its DFS tree has no edge reaching back above $u$. These are a network’s single points of failure.

Which One Do I Need?

  • How far is it? BFS. Fewest hops, nearest vertex with some property, level by level, bipartiteness.
  • What’s the structure? DFS. Cycles, whether it’s a DAG, all paths, SCCs, mazes and puzzles: anything shaped like “try a choice, undo it if it fails”.
  • What order respects the dependencies? Topological sort. Build systems, course prerequisites, package installs, and detecting circular dependencies.

Summary

Algorithm Time Space Finds
BFS $O(V + E)$ $O(V)$ Shortest paths in unweighted graphs, bipartiteness
DFS $O(V + E)$ $O(V)$ Cycles, finish order, whether it’s a DAG
Topological sort $O(V + E)$ $O(V)$ An order respecting every edge; detects cycles
Kosaraju $O(V + E)$ $O(V)$ Strongly connected components
Articulation points, bridges $O(V + E)$ $O(V)$ Single points of failure

Almost every other graph algorithm uses BFS or DFS inside it. And Euler’s lesson still holds: keep only the vertices and the edges, and the structure of the problem shows itself.
