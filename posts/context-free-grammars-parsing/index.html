Context-Free Grammars - Languages With Recursive Rules

Aug 2021
8 min read

Helpful context:

  • Automata Theory - What Machines Can and Cannot Compute

Every programming language you’ve ever used is defined by a context-free grammar. When Python says SyntaxError: invalid syntax, a parser checked your code against a grammar and found no match. When a compiler decides that 2 + 3 * 4 means 2 + (3 * 4), it’s following a precedence hierarchy written into the grammar.

Context-free grammars are the theory of syntax: which strings are valid programs, documents or expressions. Their superpower is nesting: brackets inside brackets, calls inside calls, blocks inside blocks, to any depth.

The Wall That Finite Automata Hit

A finite automaton - the machine behind regular expressions, lexers and email validators - remembers nothing except which of its fixed set of states it’s in. That is exactly why it can’t check nesting.

Take $\{0^n 1^n : n \geq 1\}$: some zeros, then the same number of ones. To check it you have to count the zeros, but a machine with, say, 50 states can’t tell 73 zeros from 74. Once the input is longer than the number of states, some state must repeat, and the machine loses count.

Programming languages are full of this shape: ((())), f(g(h(x))), every { with its }, every if with its end. Each one opens at some depth, and has to close at that same depth, which can be arbitrarily deep.

The fix is a stack: push on open, pop on close, accept when the input and the stack run out together.

The formalism that describes exactly what a stack can check is the context-free grammar.

The precise version: the Myhill-Nerode theorem

A language is regular exactly when its strings fall into finitely many equivalence classes, where two prefixes are equivalent if the same suffixes complete both of them. For $\{0^n 1^n\}$, the prefix $0^n$ can only be completed by $1^n$, so every $n$ is its own class. There are infinitely many classes, so no finite automaton can recognize the language.

Production Rules and Derivations

A grammar is a set of rules. Each rule rewrites one non-terminal (a placeholder, written in capitals) into a sequence of terminals (actual characters) and non-terminals. The grammar for $\{0^n 1^n : n \geq 0\}$ is one line:

$$S \to 0S1 \mid \varepsilon$$

$S$ either wraps itself in a 0 and a 1, or becomes the empty string $\varepsilon$. Deriving 000111:

$$S \Rightarrow 0S1 \Rightarrow 00S11 \Rightarrow 000S111 \Rightarrow 000111$$

That one rule generates exactly the language no finite automaton can recognize. So context-free grammars are strictly more powerful than regular expressions.

Formally, a CFG is a 4-tuple $G = (V, \Sigma, R, S)$: the non-terminals $V$, the terminal alphabet $\Sigma$, the rules $R$, and a start symbol $S$. Its language $L(G)$ is every terminal string you can derive from $S$.

Parse Trees and Ambiguity

Draw a derivation as a tree and you get a parse tree: the root is the start symbol, each node’s children are the rule it used, and the leaves, read left to right, spell the string. The tree is the meaning, because it decides what gets computed first.

Some grammars let one string grow two different trees. Take $E \to E + E \mid E \times E \mid \text{number}$ and the string 2 + 3 × 4:

A grammar like that is ambiguous, and for a compiler that’s a disaster: it can’t know which program you meant. The fix, shown in the third tree, splits the grammar into levels of binding strength:

$$E \to E + T \mid T \qquad T \to T \times F \mid F \qquad F \to (E) \mid \text{number}$$

  • F (factor) is an atom: a number, or a whole expression in brackets.
  • T (term) is a product of factors. It can make × but never a bare +.
  • E (expression) is a sum of terms. It’s the only level that can make +.

Since a T can never produce +, multiplication always ends up below addition in the tree, so it’s always computed first. The only way to put an addition inside a multiplication is through F → (E), which means writing the brackets yourself. The wrong reading isn’t forbidden by a rule - it simply can’t be derived.

The left recursion in E → E + T also fixes associativity: a + a + a can only parse as (a + a) + a. Add a rule E → E - T the same way and 2 - 3 - 4 correctly means (2 - 3) - 4.

Some languages are inherently ambiguous: every grammar for them is ambiguous. They’re rare, but they exist.

Chomsky Normal Form and CYK Parsing

For algorithms, it helps to have every rule in one of two shapes, Chomsky Normal Form:

$$A \to BC \qquad \text{or} \qquad A \to a$$

Every grammar can be converted to it. In CNF, a parse tree for a string of length $n$ always has exactly $2n - 1$ internal nodes.

With a CNF grammar, the CYK algorithm decides whether any string belongs to the language, using dynamic programming . The table entry $T[i][j]$ holds every non-terminal that can produce the substring from position $i$ to $j$:

  • Length 1: $A \in T[i][i]$ if there’s a rule $A \to w_i$.
  • Longer: $A \in T[i][j]$ if some rule $A \to BC$ and some split point $k$ have $B \in T[i][k]$ and $C \in T[k+1][j]$.

Fill the table from short substrings to long ones. The string is valid exactly when the start symbol ends up in $T[1][n]$. That’s $O(n^2)$ cells, $O(n)$ split points each, and every rule checked at each: $O(n^3 |G|)$.

Why compilers don’t use CYK. Real parsers are LL(1) or LR(1), restricted kinds of grammar that parse in $O(n)$ instead of $O(n^3)$. Programming languages are deliberately designed to fit these forms, so nothing useful is lost. CYK matters where grammars are messier, as in natural language processing.

Pushdown Automata: The Machine Behind CFGs

Regular languages correspond to finite automata. Context-free languages correspond to pushdown automata: a finite automaton plus a stack, exactly the machine in the first animation. At each step it can read a symbol, look at the top of the stack, push or pop, and change state.

The match is exact: a language is context-free if and only if some pushdown automaton recognizes it.

Why “Context-Free”?

The name comes from the Chomsky hierarchy of 1956, which ranks grammars by what their rules may look like.

Type Grammar Rules look like Machine
0 Unrestricted $\alpha \to \beta$, anything Turing machine
1 Context-sensitive $\alpha A \beta \to \alpha \gamma \beta$ Linear-bounded automaton
2 Context-free $A \to \gamma$ Pushdown automaton
3 Regular $A \to aB$ or $A \to a$ Finite automaton

In a context-sensitive grammar, $A$ may only be rewritten when the right things ($\alpha$ and $\beta$) surround it: the context decides. A context-free rule fires wherever $A$ appears, regardless of its surroundings.

That’s also why CFGs suit programming languages: a function body has the same valid shape whether it sits at the top level or deep inside a loop, so every piece can be checked on its own.

How we got here: linguists and compiler writers found the same idea

In 1943 McCulloch and Pitts modelled neurons in a way that led to finite automata, and by the early 1950s Kleene had characterized exactly which languages those machines describe: the regular languages.

The gap was obvious almost immediately. Natural language and mathematical notation nest: a noun phrase can contain another noun phrase (“the cat [that the dog [that the mouse bit] chased] fled”). In 1956 Noam Chomsky, working on the structure of human languages, introduced phrase-structure grammars - what we now call CFGs - to capture that recursive embedding.

In 1959 John Backus, solving a completely different problem, invented what became Backus-Naur Form to specify the syntax of ALGOL 60, so that compilers on different machines would agree on what a program meant. BNF is essentially CFG notation. A linguist and a computer scientist had arrived at the same mathematics from opposite directions, because both needed to describe nested structure with recursive rules.

Donald Knuth’s 1965 paper “On the translation of languages from left to right” introduced LR parsing, the basis of most production compilers. Parser generators like yacc and later ANTLR made it practical, and every compiler you’ve used descends from this work.

What Context-Free Grammars Cannot Do

$\{a^n b^n c^n : n \geq 0\}$, with equal numbers of $a$, $b$ and $c$, is not context-free. One stack can match two counts, but not three: checking the $c$’s needs the count of $a$’s, which was used up matching the $b$’s.

The pumping lemma for context-free languages makes this precise. Any long enough string in a CFL splits as $uvxyz$, where $v$ and $y$ can be repeated any number of times and the result stays in the language. But $v$ and $y$ together can touch at most two of the three blocks, so pumping always breaks one of the balances.

Where CFGs Appear

  • Compilers. Every front end is built on a grammar, and parser generators like yacc and ANTLR build the parser straight from it.
  • Data formats. JSON, XML and most structured formats have context-free grammars.
  • Natural language. Noun phrases inside verb phrases inside sentences: phrase-structure grammars for English are CFGs, with many complications added.
  • Biology. RNA folds into nested base pairs, and CYK-style parsing predicts the most likely folding.

Summary

Machine Grammar Memory Can recognize
Finite automaton Regular None beyond its state $\{w : w \text{ ends in } 01\}$
Pushdown automaton Context-free One stack $\{0^n 1^n : n \geq 0\}$
Turing machine Unrestricted Unbounded tape $\{a^n b^n c^n : n \geq 0\}$

Context-free grammars can count and match nesting, which regular languages can’t. They can’t enforce three-way balance, which needs more than one stack. CYK parses any of them in $O(n^3)$; the LL and LR parsers inside real compilers handle the practical subset in $O(n)$.
