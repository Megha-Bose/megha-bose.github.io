Constraint Satisfaction - Searching Smart, Not Exhaustively

Aug 2021
5 min read

Helpful context:

  • Dynamic Programming - Never Solve the Same Problem Twice
  • Graph Algorithms & Traversal - Maps, Networks, and Hidden Order

A Sudoku has 81 cells, each holding a digit from 1 to 9. Trying every possible grid means about $9^{81} \approx 2 \times 10^{77}$ of them, close to the number of atoms in the observable universe. A backtracking solver with constraint propagation solves any Sudoku in milliseconds.

The difference isn’t hardware. It’s realizing that almost every grid can be ruled out before you look at it. That’s the central idea of constraint satisfaction: constraints aren’t obstacles, they’re information.

The Framework

A constraint satisfaction problem (CSP) has three parts:

  • Variables $X_1, \ldots, X_n$: the things to decide.
  • Domains $D_1, \ldots, D_n$: the possible values for each.
  • Constraints: rules that valid combinations must obey.

A solution gives every variable a value without breaking any rule. Sudoku: 81 cell variables, domain 1 to 9, and “all different” in every row, column and box. Map coloring: one variable per region, domain {red, green, blue}, and “neighbours differ”. The same algorithm handles both.

Backtracking Search

Depth-first search over partial assignments: pick an unassigned variable, try a value, recurse. If a rule breaks, undo the last choice and try the next value. If every value fails, back up further.

Backtrack(assignment):
    if assignment is complete: return assignment
    X = choose an unassigned variable
    for v in the values of X:
        if v is consistent with assignment:
            assignment[X] = v
            if Backtrack(assignment) succeeds: return it
            remove X from assignment          // undo: backtrack
    return failure

Unpruned, that can explore every combination, $\prod_i |D_i|$ of them, exponential in $n$. Everything that follows is about pruning earlier. Here’s the difference one idea makes:

Plain backtracking tests every square, attacked or not, and only notices a dead end on arriving there. Forward checking crosses off the squares each new queen attacks in every row below, so attacked squares are never even tried, and an empty row is spotted a row early. Same answer, about a fifth of the work.

Forward Checking

After assigning $X_i = v$, remove from each unassigned neighbour’s domain every value that conflicts with $v$. If any domain becomes empty, backtrack now, without recursing into a subtree that can’t succeed. It only looks one step ahead, but it’s cheap and often enough.

Arc Consistency: Propagating Further

Arc consistency pushes the same idea through chains of constraints. An arc $(X_i, X_j)$ is consistent if every value of $X_i$ has at least one compatible value of $X_j$, its support. A value with no support can never appear in a solution, so delete it immediately.

AC-3 keeps a worklist of arcs. Whenever a domain shrinks, the arcs pointing into that variable go back on the list, since their supports might have just disappeared:

AC3(csp):
    queue = every arc (Xi, Xj)
    while queue is not empty:
        (Xi, Xj) = dequeue
        if Revise(Xi, Xj):                     // removed something from D[Xi]
            if D[Xi] is empty: return false     // no solution
            for each other neighbour Xk of Xi:
                enqueue (Xk, Xi)
    return true

Revise(Xi, Xj):
    removed = false
    for v in D[Xi]:
        if no w in D[Xj] is compatible with v:
            delete v from D[Xi]; removed = true
    return removed

With $e$ arcs and domains of size $d$, each arc returns to the queue at most $d$ times, and each Revise costs $O(d^2)$: $O(ed^3)$ in total.

Variable Ordering: Fail First

Which variable you assign next matters enormously.

  • Minimum remaining values (MRV): choose the variable with the fewest legal values left, $X^* = \arg\min |D_X|$. If one has a single option, there’s no real choice; if one has zero, you’ve found a dead end immediately. Tackling the most constrained variable first discovers failures while the subtrees beneath them are still small.
  • Degree heuristic: to break MRV ties, choose the variable involved in the most constraints with unassigned variables, since it prunes the most.

Sudoku: Propagation Nearly Removes the Search

  1. Propagate the given clues. In many easy puzzles this alone leaves every cell with one candidate.
  2. Otherwise, pick the cell with the fewest candidates (MRV).
  3. Assign a value, propagate, recurse; backtrack when a domain empties.

Expert puzzles need a few guesses, and the very hardest need deeper search, but even those finish in milliseconds because so little of the space survives propagation.

“Isn’t backtracking just brute force with early stopping?" In the worst case, yes: it’s still exponential. But on structured problems, propagation and fail-first ordering shrink the effective branching factor from 9 to about 1 for most Sudoku cells. Exponential worst case, near-linear in practice.

Graph Coloring and Hardness

Graph coloring is the general CSP behind map coloring: color the vertices so neighbours differ, with as few colors as possible. Every planar map needs at most four colors (the four-color theorem), but in general deciding whether $k$ colors suffice is NP-complete for $k \geq 3$. Two colors is easy: that’s just checking bipartiteness with BFS, $O(V + E)$. Generalized $n^2 \times n^2$ Sudoku is NP-complete as well; the fixed $9 \times 9$ size is what keeps the real puzzle easy.

Summary

Technique What it does Cost
Backtracking Depth-first over partial assignments $O(d^n)$ worst case
Forward checking Prune neighbours' domains after each assignment Cheap; catches dead ends a step early
AC-3 Propagate constraints through chains $O(ed^3)$ per run
MRV Assign the most constrained variable first Negligible
Degree heuristic Break MRV ties by constraint count Negligible

Every constraint you propagate is a branch of the search tree you never have to explore. The art is getting that information out cheaply and early.
